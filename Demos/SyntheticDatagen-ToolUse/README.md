# Synthetic Data Generation for Tool-Calling Fine-Tuning

This training-only run fine-tunes the exact Azure AI Foundry catalog model **`OpenAI-OSS / gpt-oss-120b / version 1`** to call a catalog of tools correctly, using **synthetic training data generated by the Foundry Data Generation API** from a static tool spec — no production agent traffic required.

## What it shows

End-to-end, with no manual data labeling:

1. **Convert** an OpenAI chat-completions tool catalog to OpenAPI 3.0 (the format the Foundry datagen API expects)
2. **Upload** the OpenAPI spec to your Foundry project
3. **Generate** three batches with `max_samples=60` per batch using the `ToolUseFineTuning` recipe
4. **Split** the exact returned, deduplicated rows 80% / 10% / 10%
5. **Submit** one `GlobalStandard` fine-tuning job (3 epochs, learning-rate multiplier 1.0)
6. **Monitor** training to completion
7. **Download** service result files
8. **Report** training/validation loss and token accuracy without deployment or inference

No base or fine-tuned deployment is created or called, and no inference comparison is performed.

The notebook uses the current Foundry SDK 2.x shape:

- `AIProjectClient` is constructed from `AZURE_AI_PROJECT_ENDPOINT` with `DefaultAzureCredential`.
- Data generation uses the SDK's native long-running-operation poller. In `azure-ai-projects` 2.x this operation remains under `project.beta.datasets`.
- Files, inference, and fine-tuning use only the documented client returned by `AIProjectClient.get_openai_client()`.

## Actual default contract and prior documentation discrepancies

The notebook is authoritative:

- generation: 3 requests, each with `max_samples=60`
- split: deterministic seed-42 80% train / 10% validation / 10% held-out test
- training: 3 epochs, learning-rate multiplier 1.0, `GlobalStandard`
- tools: all 15 tools in `fixtures/zava_tools_openai.json`

The earlier README said "~50" generated examples and described the fixture as a 6-tool catalog. Both differed from the notebook and fixture. The service can return fewer rows than `max_samples`; the notebook records and trains on the exact returned unique rows without padding or substitution.

## Prerequisites

- An Azure AI Foundry project (`https://<resource>.services.ai.azure.com/api/projects/<project>`) with:
  - One **teacher** model deployment (e.g. `gpt-4.1` or `gpt-5.4`) for the datagen service to call
  - `gpt-oss-120b` version 1 available for `GlobalStandard` fine-tuning
- A credential supported by `DefaultAzureCredential` with access to the project. For local development, `az login` is sufficient.
- Python 3.11+ with:

```bash
pip install "azure-ai-projects>=2.7,<3" "azure-identity>=1.26,<2" jupyter
```

## Run it

```bash
export AZURE_AI_PROJECT_ENDPOINT="https://<training-resource>.services.ai.azure.com/api/projects/<training-project>"
export AZURE_GENERATION_PROJECT_ENDPOINT="https://<generation-resource>.services.ai.azure.com/api/projects/<generation-project>"
export AZURE_TEACHER_DEPLOYMENT="gpt-4.1"
export AZURE_STUDENT_MODEL="gpt-oss-120b"
export AZURE_FINE_TUNING_TRAINING_TYPE="GlobalStandard"

jupyter notebook notebook.ipynb
```

No API key, Azure OpenAI account endpoint, account name, subscription ID, resource group, or raw management URL is required.

The checked run first attempted Switzerland North, where the project file API returned persistent 404s for newly uploaded files. It then failed over to West US 3, preserving the exact generated data and split. East US 2 is prohibited. Generation may use a separate project with a teacher deployment, but the exact downloaded data is uploaded to the training project. To re-monitor an existing job, set `AZURE_FINE_TUNING_JOB_ID`.
